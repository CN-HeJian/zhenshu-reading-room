# 阅读心路上下文预算设计

## 目标

让每周 DeepSeek 阅读心路分析在数据长期增长后仍保持稳定，不把全部笔记和历史正文直接发送给模型，同时保留跨年份的阅读变化线索。

## 方案

采用分层取样与固定预算的单次请求方案：

1. 证据层保留最早锚点、最近变化，以及按月份和类别挑选的高信号笔记，最终默认不超过 60 条。
2. 每条证据的摘录和想法分别限制长度，避免单条异常长文本占满上下文。
3. 历史归档只发送最近 24 期的压缩摘要；每期只保留标题、核心判断和阶段标题/短叙述，不发送完整历史正文。
4. 长期记忆使用独立的压缩结构，限制阶段、转折、主题和类别迁移的数量与长度。
5. 构造请求后按字符数估算 Token，设置固定输入预算。若超预算，按“减少历史细节 → 减少辅助证据 → 保留全程锚点”的顺序自动降级；仍超预算则在调用 API 前失败并给出明确错误。

## 数据流

```text
微信读书数据
    ↓
分层取样（早期 / 近期 / 月份 / 类别）
    ↓
证据与归档压缩
    ↓
固定上下文预算预检
    ↓
DeepSeek 单次 JSON 分析
    ↓
阅读心路与长期记忆
```

## 边界与取舍

- 不采用多轮摘要，避免每周任务变慢并增加 API 成本。
- 不删除本地历史归档；压缩只作用于发送给模型的输入。
- 最早和最近证据为强保留项，中间证据允许按预算均匀抽样。
- 预算使用保守的字符估算，不依赖特定模型的 tokenizer；输出上限仍由 API 请求的 `max_tokens` 控制。

## 验证标准

- 人工构造大量笔记与归档时，请求输入始终低于固定预算。
- 输入仍包含最早和最新阶段的证据，并包含多个时间段/类别。
- 普通小数据分析的现有行为和 JSON 输出结构不变。
- 超预算不会发起 DeepSeek 请求，而是在本地返回可诊断错误。
